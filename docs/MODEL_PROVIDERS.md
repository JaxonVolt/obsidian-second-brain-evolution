# 模型接入指南

## 先理解运行结构

插件不会为每种模型重写一套知识工作流。Codex CLI 负责会话、工具调用、权限和文件操作，用户选择的模型负责推理与生成。这样更换模型后，今日笔记、问库、收件箱分流和确认写入仍使用同一套规则。

可接入的范围：

- Codex 账户中的可用模型。
- Ollama 或 LM Studio 中已经下载并启动的本地模型。
- 实现 OpenAI Responses API 的云端、自建或局域网模型服务。

“端点能连接”不等于“完整工作流可用”。要可靠执行知识演化任务，模型应支持流式输出、工具调用，并具备足够的上下文窗口。只支持普通文本生成的模型可能可以回答问题，但无法稳定调用文件工具或输出结构化分流结果。

## Codex 账户

1. 安装并登录 Codex CLI。
2. 在插件设置的“模型提供商”中选择“Codex 账户”。
3. 点击“测试连接”确认已检测到 Codex CLI。
4. 快速通道使用 Terra，中等推理；深度通道使用 Sol，高推理。

费用和额度由当前 Codex 账号与套餐决定。

## Ollama 本地模型

1. 安装并启动 Ollama。
2. 下载一个支持工具调用的模型，例如在终端运行 `ollama pull gpt-oss:20b`。
3. 在插件设置中选择“Ollama（本地）”。
4. “快速模型”填写 Ollama 中的完整模型名，例如 `gpt-oss:20b`。
5. “深度模型”可以填写更强模型，也可以留空沿用快速模型。
6. 点击“测试连接”，确认能够读取 `http://127.0.0.1:11434` 的模型列表。

本地推理没有云端模型调用费，但会消耗电脑的内存、显存、电力和运行时间。模型越大，响应通常越慢。

## LM Studio 本地模型

1. 在 LM Studio 中下载并加载模型。
2. 启动 Local Server，保持默认地址 `http://127.0.0.1:1234`。
3. 在插件设置中选择“LM Studio（本地）”。
4. 填写 Local Server 模型列表中显示的模型 ID。
5. 点击“测试连接”。

如需修改端口或连接局域网中的另一台电脑，请改选“自定义 Responses API”。

## 自定义 Responses API

服务接口要求：

- 必须提供 `POST /v1/responses`：用于流式模型响应。
- 建议提供 `GET /v1/models`：用于插件连接检查和读取模型列表；缺少它时，连接检查会失败，但不代表 Responses 接口一定不可用。

配置步骤：

1. 选择“自定义 Responses API”。
2. API 基础地址填写到版本层，例如 `https://models.example.com/v1`。
3. 在“API 密钥”一栏直接新建或选择密钥。密钥由 Obsidian 密钥库加密保存，插件设置只记录密钥名称。
4. 如果原来已经通过系统环境变量配置密钥，也可以不选择密钥，在“旧版环境变量”中保留变量名。
5. 分别填写快速模型和可选的深度模型。
6. 点击“测试连接”，再新建对话做一次只读问答测试。

直接新建密钥后无需重启 Obsidian。只有修改旧版系统环境变量时，才需要完全退出并重新打开 Obsidian。

插件只支持 Codex CLI 当前支持的 Responses 协议。只有 Chat Completions 接口、没有 Responses 兼容层的服务不能直接接入。

## 推理强度

Codex 账户默认按快速/深度通道发送对应推理强度。本地或自定义模型默认关闭该参数，因为很多模型不认识 `reasoning effort`。只有服务文档明确声明支持时，才开启“发送推理强度”。

## 切换后的检查顺序

1. 连接测试能看到模型。
2. 新建对话，询问一个不需要写文件的简单问题。
3. 运行一次知识库问答，确认工具调用正常。
4. 用少量测试内容运行收件箱分流，检查 JSON 结构和中文质量。
5. 确认无误后再用于真实笔记。

切换提供商后建议新建对话，避免旧会话上下文与新模型能力不一致。
