# 隐私与数据说明

## 本地保存的数据

插件会在用户自己的 Obsidian vault 中保存笔记、收件箱内容、会话历史、分流账本和插件设置。上述内容不属于本 GitHub 仓库，也不会被仓库自动收集。

首次初始化向导只在用户确认后创建空白通用骨架和模板，不会读取现有笔记来推断画像，也不会覆盖已有文件。

## 模型请求

当用户主动发起对话、问库或收件箱分析时，相关提示词和上下文会交给本机 Codex CLI，再由用户选择的模型提供商处理。使用 Codex 账户或自定义远程接口时，数据如何传输、计费和保留取决于对应提供商；使用本机 Ollama 或 LM Studio 时，模型推理请求通常留在本机。普通快速捕获本身不调用模型。

插件设置只保存所选密钥的名称，不保存实际密钥；真实密钥由 Obsidian 密钥库加密保存，并且只在启动模型子进程时临时注入环境。旧版环境变量方式仍可兼容。请勿把密钥写进服务 URL、笔记、截图或 Issue。连接测试会向所选服务的模型列表接口发起请求。

## 微信远程入口

- 连接需要用户本人扫码确认。
- 连接凭据保存在插件本地数据中；Windows 上使用当前系统用户范围的加密保护。
- 收到的文字、图片和文件写入用户自己的 vault。
- 插件只处理已绑定会话的消息，不提供公开机器人入口。
- 转发卡片可能无法完整提取，插件会尽量保留可识别信息。

## 公开仓库不包含的内容

- 个人画像和真实笔记。
- 微信账号、令牌、二维码和加密后的凭据文件。
- Codex 会话、运行账本和本机路径。
- 模型 API 密钥和本地模型服务配置。
- `.env`、`data.json`、vault 和调试日志。

提交 Issue 或 Pull Request 前，请再次检查截图、日志和测试夹具是否已经脱敏。
